# ImagineVR

Hacklanta 2 submission (Creative track).

ImagineVR is a voice-driven VR experience for Meta Quest 3S. You start in a dark room facing a
terminal that behaves like an agentic coding CLI, say what you imagine, and the world is built
around you in real time.

## How it fits together

The headset is deliberately thin. It records push-to-talk audio, sends it to the server, and
plays back what comes out.

1. The server transcribes the audio with Whisper.
2. It sends the text and the current world state to a model through OpenRouter.
3. It validates the reply and streams it back as **ImagineScript**: one JSON statement per
   line (`sky`, `terrain`, `spawn`, `kit`, `weather`, `say`, ...).
4. The headset plays each statement into the terminal and the world as it arrives.

```
client/   Unity project (Quest 3S, plus a desktop mode for working without a headset)
server/   Legacy launch compatibility; backend implementation is in openrouter-api/
openrouter-api/ FastAPI server: speech to text, model call, validation, streaming
shared/   catalog.json (generated by Unity, read by the server) and examples/*.ndjson
specs/    Spec Kit documents: spec, plan, tasks, contracts
scripts/  unity.ps1, a Windows wrapper for Unity command-line runs
```

The contracts between the two halves are in `specs/001-voice-world-builder/contracts/`
(`server-api.md`, `scene-language.md`, `catalog.md`). `scene-language.md` and `catalog.md` lag
the code: they do not yet describe `weather`, `physics`, `ride`, `goal`, `player`, `behavior`, `solid`, `path`, vector `scale`
and `rot`, or dotted ids. `openrouter-api/imagine/prompt.md` is the current reference.

## Setting up a machine

- `git`, `git lfs` (run `git lfs install` once), and `uv`.
- Unity Hub, signed in, and **Unity 6000.3.26f1** with **Android Build Support** (SDK/NDK and
  OpenJDK). Only needed for the client.

`client/Library/`, `client/Temp/`, `client/Logs/`, `client/Snapshots/` and `server/.venv/` are
caches. Do not copy them between machines; Unity and `uv` rebuild them.

## Server

```
cd openrouter-api
python -m uvicorn app.main:app --host 127.0.0.1 --port 8080
python scripts/smoke.py
```

Configuration is environment variables; copy `openrouter-api/.env.example` to `openrouter-api/.env`. With no
`OPENROUTER_API_KEY` the server uses an offline keyword director, so "I want to see a golf
course" or "make it sunset" work end to end without a model. Keys never go in the repo.

Routes: `POST /v1/turn` (audio or text in, streamed NDJSON out), `POST /v1/session/reset`,
`GET /v1/health`, `GET /v1/audio/{clip_id}`. Requests carry `X-App-Token`, `X-Session-Id` and
`X-Catalog-Version`.

Things to know:

- Anything in front of the app (Caddy, nginx, a load balancer) must not buffer responses, or
  the streaming breaks.
- The backend uses Python 3.13 and local faster-whisper transcription on the
  4-vCPU / 8-GB VM. No speech provider key is required; OpenRouter receives text only.
- WAV is decoded by hand in `stt.py` because faster-whisper's decoder breaks with the current
  PyAV.
- On Windows use `127.0.0.1`, not `localhost` (two-second IPv6 delay).
- The world-building backend is not deployed yet. Activation and secrets are documented
  in `openrouter-api/README.md`; deployments continue to use that folder.
- `python scripts/smoke.py` checks a running server against the things people actually say.
  Run it after adding an OpenRouter key and after changing `prompt.md`.

## Client

Open `client/` in Unity 6000.3.26f1, open `Assets/ImagineVR/Scenes/Main`, press Play. No
headset, server or keys are needed for the built-in demos.

- **F1** to **F8** play built-in demos, **B** cycles through all 32, **F12** returns to the
  dark room.
- Hold the **right mouse button** to look around.
- **Enter** types a request and **Space** speaks one (both need the server), **E** grabs,
  **left click** uses the held thing, **R** recentres the terminal.
- **W A S D** walks you around, or drives whatever you are riding (the right thumbstick in
  the headset).

The server URL and app token are in the `ImagineSettings` asset
(`client/Assets/ImagineVR/Resources/`). The token must match `IMAGINE_APP_TOKEN`.

### Unity from the command line

Unity Hub must be running and signed in, or Unity exits with "No valid Unity Editor license
found".

macOS, from the repo root:

```
UNITY=/Applications/Unity/Hub/Editor/6000.3.26f1/Unity.app/Contents/MacOS/Unity

# compile only
$UNITY -batchmode -nographics -quit -projectPath client -logFile -

# export shared/catalog.json and embed the demo scripts (commit the result)
$UNITY -batchmode -nographics -quit -projectPath client -logFile - \
  -executeMethod ImagineVR.EditorTools.Catalog.Export

# render demo worlds to PNG files (needs a GPU: no -nographics, and no -quit)
$UNITY -batchmode -projectPath client -logFile - \
  -executeMethod ImagineVR.EditorTools.Snapshot.Run \
  -snapScripts "$PWD/shared/examples/03-forest-dawn.ndjson;$PWD/shared/examples/04-beach.ndjson" \
  -snapOut "$PWD/client/Snapshots" -snapTimes 9 -snapYaws 0,120,240
```

Windows uses the wrapper, which takes paths relative to the repo root:

```powershell
./scripts/unity.ps1                                                     # compile only
./scripts/unity.ps1 -Method ImagineVR.EditorTools.Catalog.Export
./scripts/unity.ps1 -Method ImagineVR.EditorTools.Catalog.CheckAssets   # build every mesh, list triangle counts
./scripts/unity.ps1 -Method ImagineVR.EditorTools.Snapshot.Run -Graphics -NoQuit -TimeoutSec 600 `
  -Extra '-snapScripts','shared/examples/03-forest-dawn.ndjson','-snapOut','client/Snapshots','-snapTimes','9','-snapYaws','0,120,240'
./scripts/unity.ps1 -Method ImagineVR.EditorTools.Builder.BuildAndroid -Target Android -NoQuit -TimeoutSec 3600
```

Do not pass a broad `-Show` pattern to `unity.ps1`; a loose pattern prints thousands of lines.

`-snapSheet 'furniture:0;party:0'` in place of `-snapScripts` renders a contact sheet of
library assets by category and page (21 per page).

Rendering demos fills in the dynamic font asset
`client/Assets/ImagineVR/Resources/Fonts/ImagineMono.asset`. Do not commit that change; restore
the file with `git checkout`.

### Conventions that are easy to break

- **Asset recipes**: metres, +Y up, origin at the centre of the base, front faces +Z. Tools
  stand upright with the grip at the origin; in the hand their +Y becomes the controller's
  forward. Things meant to be tinted are modelled white.
- **MeshBuilder fixes triangle winding itself** from the `outside` hint each face is given.
  Recipes never choose a winding order. Negative-height `Cyl`/`Cone` hang downward.
- **Emission**: `Emit(always, night)`; `Window()` is glass by day and warm light at night;
  `Glow()` adds a halo quad in submesh 1 (drawn by the Glow shader).
- **Use `AssetDef.Bounds`, not `Mesh.bounds`**. Mesh bounds are padded for halos.
- **Lighting never uses URP lights.** `SkySystem` sets `_Im*` shader globals every frame and
  every ImagineVR shader lights and fogs itself from them (`ImagineCommon.hlsl`).
- **Shaders live in `Resources/Shaders`** so builds include them; materials are made in code.
- **A MonoBehaviour or ScriptableObject that an asset or scene refers to needs its own file
  named after the class.** Classes only ever added with `AddComponent` can share files.
- **The terminal font asset is dynamic and starts empty**: test glyphs with
  `HasCharacter(c, false, true)`. JetBrains Mono has no braille, ★ or ⎿; the terminal falls
  back to other characters on its own.
- **Kits** fill in a missing sky and terrain themselves, are rebuilt when the ground changes,
  and own any loose props they create (`KitContext.Loose`), removed with the kit.
- **Batch mode**: `WaitForEndOfFrame` never fires; instanced draws must be queued again
  (`Objects.Render()`) before a manual `Camera.Render()`.
- **After changing assets or kits, re-export the catalog** and commit `shared/catalog.json`
  and `CatalogVersion.txt`. The server builds the model's prompt from it.

## Different from the plan, on purpose

- No XR Interaction Toolkit: hands and grabbing are a small custom system on the Input System.
- Library entries are code, not ScriptableObjects.
- Sounds are synthesised. A clip at `Resources/Sfx/<name>` or `Resources/Ambience/<id>`
  replaces the synthesised one.

## Backend

The FastAPI backend is in [openrouter-api](openrouter-api/README.md).
GitHub Actions tests it and deploys backend changes on `main` to the Vultr VM.
See the backend README for the required GitHub secret and deployment activation steps.

## Infrastructure

The Ubuntu server on Vultr is managed by Terraform in [infra/vultr](infra/vultr/README.md).
That directory contains the VM, firewall, SSH public key, first-boot configuration,
and import declarations for the existing server, plus connection and team setup instructions.
The VM's Python service and nginx setup are recorded in `infra/deploy/`.
