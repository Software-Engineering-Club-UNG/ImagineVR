## Contract and architecture

New runtime-blueprints-v1 capability; session-scoped blueprint/blueprint_remove and blueprint_edit commands. Definitions contain parts (shape or catalog asset, parent, local transforms, color/emission, collider), sockets, animations and capabilities. Spawn/give and rule spawn reference blueprint IDs. Full replacement creates a new immutable revision for future copies. blueprint_edit targets an instance/group, applies a complete validated recipe as an instance-local revision, preserving entity ID/pose/health/rules. Build first, swap atomically.

Generic Actor component owns locomotion and named states. Part animation drives local transforms. Contact sensors and socket-based projectiles connect to existing events/actions, not executable scripts. Session player health default100, locally opt-in, defeat stops damage; no camera movement.

Limits64 definitions,64 parts,depth8,8000triangles,16colliders/animations; existing interaction/creature/global budgets apply. Incremental mesh assembly ~2ms/frame; labeled placeholder pending. Backend/client defensive validation, cycles/reference checks, atomic edits, resource cleanup. Legacy clients retain existing sculpt/fallback. No deployment before native acceptance.

Constitution exception: bounded declarative runtime composition is the requested expansion of baked-first demo scope, not arbitrary code or external binary generation. Runtime recipes fit procedural tier. Main remains gated on headset acceptance.
